# Glacial v1.0 remediation sequence

G045 closed the three P2 owner decisions, and G046 added versioned state
lifecycle evidence plus the mandatory deep-security gate. This revised
sequence converts the remaining P1 blockers in the 2026-07-27 audit into bounded future handoffs. It
does not authorize v1.0.0, reserve work for P3 polish, or permit a handoff to
weaken an existing safety or release gate.

## G046 — Versioned state lifecycle and recovery

- **Contract IDs:** `V1-SCAN-006`, `V1-DATA-001`, `V1-DATA-002`, `V1-DATA-004`, `V1-DATA-005`
- **Exact outcome:** inventory every persistent mutation; introduce an explicit database schema/migration and compatibility policy; add supported-predecessor fixtures, rollback/fault tests, backup/recovery guidance, and exact retention/reset behavior.
- **Why together:** these gaps share the SQLite/application-state trust boundary and must agree before desktop upgrade or uninstall behavior can be accepted.
- **Expected evidence:** schema/version documentation, migration fixtures, fault-injection results, SQLite integrity/readback, and a state-retention matrix.
- **Dependencies:** none.
- **Desktop computer-use acceptance:** limited interruption/recovery observation is required; full installer/portable acceptance waits for G055.
- **Release packaging/signing:** not required.
- **Validation scope:** targeted database, project lifecycle, scan persistence, baseline/profile, and interruption tests only.

## G047 — Persisted and exported data privacy boundary

- **Contract IDs:** `V1-FS-006`
- **Exact outcome:** enumerate every database, log, diagnostic, report, brief, package, release-log, and export field; document data classes and add focused tests preventing secrets, unnecessary project content, and absolute host-path disclosure.

- **Dependencies:** G046 state inventory.
- **Desktop computer-use acceptance:** focused log/report/export inspection required.
- **Release packaging/signing:** not required.
- **Validation scope:** targeted evidence, report, remediation, diagnostic, and persistence tests.

## G048 — Installed and portable desktop lifecycle

- **Contract IDs:** `V1-DESKTOP-002`, `V1-DESKTOP-003`, `V1-DESKTOP-004`, `V1-DESKTOP-005`

## G052 — Codex Security Deep Security Scan

- **Contract ID:** `V1-SEC-007`
- **Target:** entire `Z:\CodexProjects\Glacial` repository.
- **Scope:** repository-wide.
- **Timing:** after G051 and before any release-candidate construction.
- **Source:** clean aligned `main`.
- **Mode:** Codex Security **Deep Security Scan**, not a normal code review and not a diff scan.
- **Repository edits:** prohibited during the scan.
- **Required phases:** repeated independent discovery, canonical repository-specific threat-model synthesis, coverage ledger, centralized validation, attack-path and severity analysis, detailed finding write-ups, a hardening portfolio when reportable findings exist, and canonical generated report completion.
- **Minimum inspected surfaces:** Python backend and API authentication; SQLite state/migrations; filesystem confinement; path canonicalization; reparse-point, junction, symlink, and hardlink behavior; hostile scanner input; rendering and inert-text boundaries; Remediation Brief/Package generation; ZIP/checksum semantics; the Tauri boundary; Rust backend-supervisor lifecycle; token/diagnostic handling; release/signing scripts; dependency/build supply chain; installer/portable logic; and every other high-impact surface identified by the threat model.
- **Required output:** complete generated Codex Security artifacts and the G052 handoff summary, including every deferred or incomplete surface.
- **Release effect:** every reportable finding blocks release-candidate construction. Deferred or incomplete coverage remains explicit and may itself block authorization based on materiality. “No findings” is not proof that Glacial is secure.
- **Validation scope:** owned by the Codex Security Deep Security Scan workflow rather than ordinary project tests.

## G053 — Security Finding Remediation and Closure

- **Contract ID:** `V1-SEC-007`
- **Input:** the exact completed G052 scan and every reportable finding.
- **Outcome:** remediate every validated reportable finding in bounded, reviewable changes. Do not combine unrelated findings into one opaque patch.
- **No-findings case:** document closure, coverage limitations, and evidence without manufacturing changes.
- **Required validation:** every finding receives post-fix validation and attack-path closure.
- **Rediscovery:** rerun focused discovery or a broader security scan when remediation materially changes shared controls or high-impact surfaces.
- **Audit:** update readiness only after every reportable finding is closed.
- **Release effect:** release-candidate construction remains blocked while any reportable finding or materially unresolved deferred row remains.
- **Packaging/signing:** not required.

## G056 — Final Signing, Artifact Verification, and v1 Authorization

- **Contract IDs:** `V1-SEC-005`, `V1-REL-004`, `V1-REL-005`, `V1-REL-006`
- **Exact outcome:** independently reverify every candidate PE signature and RFC 3161 timestamp, artifact hash/inventory/manifest/source alignment, release notes, GitHub Release contents plan, rollback/withdrawal procedure, security closure, and all contract closures; then request explicit owner authorization for v1.0.0.
- **Why together:** final authorization must operate on immutable accepted bytes and one complete evidence set.
- **Expected evidence:** independent verification report, signer/chain evidence, published hash/signing identity plan, rollback drill, final audit with no P0/P1, and explicit authorization.
- **Dependencies:** all previous handoffs, especially closed G052/G053 security evidence, unchanged G054 bytes, and passing G055 acceptance.
- **Desktop computer-use acceptance:** no new broad pass unless bytes or supported environment changed.
- **Release packaging/signing:** final verification required; no rebuild after acceptance. Git tag/GitHub Release creation occurs only in a separately authorized release action after this gate passes.
- **Validation scope:** artifact/evidence consistency and contract closure only.

## Recommended final order

1. **Gap remediation:** G046 → G047 → G048 → G049 → G050 → G051.
2. **Deep repository security assessment:** G052 runs the no-edit repository-wide Codex Security Deep Security Scan.
3. **Security remediation and closure:** G053 closes every reportable finding and material deferred surface before candidate construction.
4. **Release-candidate construction:** G054 freezes traceable installer and portable bytes plus metadata.
5. **Installed and portable acceptance:** G055 exercises only those frozen bytes on the declared support matrix.
6. **Final signing, artifact verification, contract closure, and explicit v1 authorization:** G056 operates on the accepted unchanged bytes.
7. **Publication:** tag and GitHub Release creation occur only in a separately authorized action after G056 passes.
