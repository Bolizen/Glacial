# Glacial v1.0 readiness contract

This contract defines the minimum evidence required to authorize Glacial v1.0.0. It is a release gate, not a claim that Glacial can prove a project safe, clean, secure, or fully verified. Requirements are permanent: text may be clarified, but identifiers must not be reused or renumbered.

For every requirement, **release-blocking** means v1.0 authorization must stop when the requirement is not completely demonstrated. **Owner waiver** means a named project owner may accept the stated limitation in writing; a waiver may not override a P0 safety or integrity invariant. Unless stated otherwise, the supported v1.0 product boundary is a non-elevated Windows x64 desktop application using the owned local backend.

## Permanent Windows distribution decision

> Glacial v1 does not provide or support a portable binary edition. The supported Windows product is the installed NSIS edition. Unpacked development builds, test fixtures, build staging directories, and source checkouts are not portable product distributions. A portable edition may only return through a future explicit product decision with its own state, upgrade, security, filesystem, signing, recovery, and acceptance contract.

GitHub-generated source archives are source snapshots, not Glacial binary distributions. Copying, unpacking, or relocating installed application files is unsupported and does not create another product edition. This scope decision does not satisfy any installed-edition lifecycle, release, signing, recovery, reset, upgrade, uninstall, or acceptance requirement.
