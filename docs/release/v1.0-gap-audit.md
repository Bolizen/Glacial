### Five most important current gaps

1. **State upgrade and recovery contract:** schema migrations, interruption recovery, compatibility boundaries, retention, reset, and uninstall behavior are not comprehensively specified or accepted (`V1-DATA-001`, `V1-DATA-002`, `V1-DATA-004`, `V1-DATA-005`).
2. **Installed and portable lifecycle evidence:** repeated launch, crash/startup failure, orphan prevention, application-data behavior, upgrade, reset, and uninstall have not been accepted on current candidate artifacts (`V1-DESKTOP-002`–`006`).
3. **Release-candidate and public-trust evidence:** no v0.9.1/v1 candidate artifacts exist, no publicly trusted signer is configured, and no current manifest/hash/signature acceptance exists (`V1-REL-003`–`006`, `V1-SEC-005`).
4. **Stable user, legal, privacy, and support documentation:** developer setup exists, but stable installation/portable/troubleshooting, support matrix, third-party notices review, privacy disclosure, private security reporting, and support policy remain incomplete (`V1-DOC-002`–`006`, `V1-SEC-006`).
5. **Whole-product accessibility baseline:** remediation modal behavior is strong, but critical-workflow keyboard coverage, minimum-size/contrast evidence, and non-color/non-pointer interaction review are incomplete (`V1-UX-001`, `V1-UX-004`, `V1-UX-005`).

### Five strongest areas already demonstrated

1. Project confinement and the narrowly bounded, confirmation-gated, atomic root `AGENTS.md` write.
2. Conservative scanner coverage, resource bounds, linked-path rejection, and refusal to equate completion with safety.
3. Project-scoped immutable scan evidence with separate reviews, baselines, comparisons, and checkpoints.
4. Snapshot-bound Agent Remediation Brief and deterministic data-only Package with fixed inventory and exact checksums.
5. Authenticated owned-backend design and fail-closed release tooling for signer identity, artifact inventory, hashes, and atomic candidate publication.

## Dependabot alert assessment

GitHub Dependabot alert #2 was read directly through authenticated GitHub REST on 2026-07-27.

- Advisory: `GHSA-r28c-9q8g-f849`
- Package/version: `postcss` 8.5.16 in `frontend/package-lock.json`
- Affected range/fix: `<= 8.5.17`; first patched version 8.5.18
- GitHub severity/CVSS: High / 7.5
- Claim: attacker-controlled CSS can use a traversing or absolute `sourceMappingURL` to disclose readable `.map` files when PostCSS previous-map loading is enabled.
- Dependency path: Vite 7.3.6 → PostCSS 8.5.16.
- Current product reachability: repository search found no PostCSS API use and no selected-project CSS path into Vite. The build processes Glacial's checked-in `styles.css`; Tauri embeds `frontend/dist`, and release inventories exclude `node_modules`.
- Static triage verdict: **not actionable to the shipped Glacial desktop attack surface, high confidence**. The required untrusted-CSS boundary is absent.
- Governance disposition: the alert remains open and is therefore `PARTIAL`/P2 under `V1-SEC-004`, not a pass. Owner must choose a narrow reviewed update or a time-bounded waiver, and the final artifact inventory must reconfirm that PostCSS is not shipped.
